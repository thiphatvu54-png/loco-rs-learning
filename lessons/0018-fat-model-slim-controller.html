Fat Model，Slim Controller：把规则放在正确的边界

目标：识别 controller 里的数据库业务逻辑，并把可复用规则下沉到 model/entity。

1. 当前 categories 已经有两个好例子

// src/models/categories.rs
pub fn search(q: Option<&str>) -> sea_orm::Select<Self> { ... }

pub async fn ensure_name_unique(
    db: &DatabaseConnection,
    name: &str,
    except_id: Option<i64>,
) -> ModelResult<()> { ... }

controller 只负责拿到参数，然后调用：

Entity::ensure_name_unique(&ctx.db, &params.name, None).await?;
let res = query::paginate(&ctx.db, Entity::search(filter.q.as_deref()), None, &pagination).await?;

2. 什么算 Fat Controller

下面这种写法把可复用的查询规则藏在 HTTP 层：

let query = Entity::find()
    .filter(categories::Column::Name.contains(q))
    .order_by_asc(categories::Column::Id);

如果后台任务、CLI Task、另一个接口也需要同样规则，就会复制代码。把它放到 Entity::search 后，所有入口共享同一个领域查询。

3. 三条边界

层负责不负责
Controller提取参数、鉴权、调用、渲染响应隐藏的业务查询细节
Model/Entityfinder、查询规则、唯一性、状态转移HTTP header 和 JSON 格式
DTO输入/输出结构数据库查询规则

4. 快速练习

  1. 找出 categories controller 中一个可以复用的查询片段。
  2. 把它设计成 impl Entity 或 impl Model 上的方法。
  3. 让 controller 只保留“提取 → 调用 → 返回”。
