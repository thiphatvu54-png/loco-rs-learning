认证与授权：知道你是谁，还要判断你能做什么

目标：区分 JWT 验证和业务授权，并在需要用户资料时使用 JWTWithUser。

1. 两个问题

问题Loco 机制结果
你是谁？auth::JWT验证 token，得到 claims.pid
你能做什么？handler/model 业务规则允许、拒绝或返回资源不存在
需要完整用户行吗？auth::JWTWithUser<users::Model>验证 token 后自动查用户

auth::JWT 不查数据库；它只验证签名和过期时间。JWTWithUser 会再按 claims 里的 pid 加载用户，查不到用户时返回 401。

如果只需要“必须登录”，用下划线变量表达“我不读取 claims”。

3. 需要当前用户时

use crate::models::users;

async fn current_user(
    auth: auth::JWTWithUser<users::Model>,
) -> Result<Response> {
    tracing::info!(user_pid = %auth.user.pid, user_email = %auth.user.email, "current user");
    format::json(serde_json::json!({
        "pid": auth.user.pid,
        "email": auth.user.email,
    }))
}

授权规则应该靠近领域对象。例如“只能修改自己的资料”需要比较 auth.user.pid 与资源的 owner_pid；“只有管理员能删除”需要角色或权限字段。当前项目的 users 表还没有 role 字段，所以只能先做身份加载，不能凭空实现管理员规则。

边界：401 表示身份无效或用户不存在；403 才表示身份有效但没有权限。业务规则决定何时返回 403。
