从零实现自定义 MiddlewareLayer

这一课真正写一个 Loco middleware：它给所有响应加 X-Admin-API: loco，再把它注册进全局栈。

1. 四个方法对应四个问题

name()      // 栈里用什么名字找到它？
is_enabled  // 当前是否参与构建？
config()    // cargo loco middleware --config 显示什么？
apply()     // 如何把它套到 Axum Router？

Loco 1.2 的 MiddlewareLayer 接收的是带 AppContext 状态的 Axum Router。它比 Routes::layer 更靠外层，作用范围是整个应用。

2. 写一个响应头 middleware

use axum::{
    http::HeaderValue,
    response::Response,
    Router as AXRouter,
};
use loco_rs::{
    app::AppContext,
    controller::middleware::MiddlewareLayer,
    Result,
};
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Deserialize, Serialize)]
pub struct AdminHeader {
    #[serde(default)]
    pub enable: bool,
}

impl MiddlewareLayer for AdminHeader {
    fn name(&self) -> &'static str {
        "admin_header"
    }

    fn is_enabled(&self) -> bool {
        self.enable
    }

    fn config(&self) -> serde_json::Result<serde_json::Value> {
        serde_json::to_value(self)
    }

    fn apply(&self, app: AXRouter<AppContext>) -> Result<AXRouter<AppContext>> {
        Ok(app.layer(axum::middleware::map_response(add_header)))
    }
}

async fn add_header(mut response: Response) -> Response {
    response.headers_mut().insert(
        "X-Admin-API",
        HeaderValue::from_static("loco"),
    );
    response
}

map_response 只改响应，不需要手动调用 next.run(req)。这适合响应头、响应包装和统一输出处理。

3. 注册到 App 的默认栈

use loco_rs::controller::middleware::{
    self, MiddlewareLayer,
};

fn middlewares(ctx: &AppContext) -> Vec<Box<dyn MiddlewareLayer>> {
    let mut stack = middleware::default_middleware_stack(ctx);
    stack.push(Box::new(AdminHeader { enable: true }));
    stack
}

把这个方法放入 impl Hooks for App。因为它被 push 到 Vec 末尾，所以它最先看到入站请求，响应头也会在最外层写回。

4. 验证闭环

cargo loco middleware --config
curl.exe -i http://127.0.0.1:5150/api/categories

检查 middleware 列表和响应头。若看不到 X-Admin-API，按顺序查：有没有覆盖正确的 Hooks::middlewares、is_enabled() 是否为 true、apply() 是否返回了新 Router。
