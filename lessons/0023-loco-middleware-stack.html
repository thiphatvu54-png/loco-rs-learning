Loco 的 MiddlewareLayer 栈：改默认栈，而不是重写应用

这是 Loco 特有的扩展点：用 Hooks::middlewares 拿到默认 middleware 栈，再用 MiddlewareStackExt 做插入、替换、删除。

1. 框架调用链

Hooks::middlewares(ctx)
    ↓
Vec<Box<dyn MiddlewareLayer>>
    ↓ 逐个调用 mid.apply(app)
Axum Router

MiddlewareLayer 必须提供四件事：稳定的 name()、开关 is_enabled()、可观察配置 config()、以及把 layer 应用到 Axum Router 的 apply()。默认栈由 Loco 构造，不需要你复制一份。

2. 在 Hooks 中替换一个默认 middleware

use loco_rs::app::{AppContext, Hooks};
use loco_rs::controller::middleware::{
    self, MiddlewareLayer, MiddlewareStackExt,
};

impl Hooks for App {
    // 其他 Hooks 方法省略
    fn middlewares(ctx: &AppContext) -> Vec<Box<dyn MiddlewareLayer>> {
        let mut stack = middleware::default_middleware_stack(ctx);

        // 仍保留原来的位置，只把 X-Powered-By 改成自己的标识
        stack.replace(
            "powered_by",
            Box::new(middleware::powered_by::new(Some("admin-api"))),
        );

        stack
    }
}

结果是响应头变为 X-Powered-By: admin-api。replace 按 name() 找第一个匹配项；找不到时保留原栈并记录 warning。

3. 插入位置和请求顺序

stack.insert_after(
    "request_id",
    Box::new(middleware::powered_by::new(Some("admin-api"))),
);

栈的 Vec 顺序是构建顺序，但请求顺序是 LIFO：后面的 middleware 先接到请求。insert_after("request_id", ...) 会让新 middleware 在请求进入时先于 request_id 看到请求。

方法找不到目标时
insert_before追加，并记录 warning
insert_after追加，并记录 warning
replace保持不变，并记录 warning
delete保持不变，并记录 warning

4. 这和 Routes::layer 的分界

Hooks::middlewares(...) // 全应用，遵守 Loco 的 MiddlewareLayer 协议
Routes::layer(...)      // 一个 Routes 组，直接套 Tower Layer

需要配置、出现在 Loco middleware 栈、可被统一 introspect 时，用 MiddlewareLayer；只影响一组 controller 时，用 Routes::layer。

  1. 把 powered_by 替换为 admin-api。
  2. 运行应用后，用 curl.exe -I http://127.0.0.1:5150/api/categories 检查响应头。
  3. 再把 replace 改成 delete，观察响应头和日志差异。
