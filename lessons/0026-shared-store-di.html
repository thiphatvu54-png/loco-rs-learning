SharedStore：把运行时服务注入 handler

这是 Loco 的类型化依赖注入入口：在 after_context 里放入服务，handler 用 SharedStore<T> extractor 取出。

1. 启动时装配，请求时读取

Hooks::after_context(ctx)
    ↓ ctx.shared_store.insert(RatePolicy)
AppContext 进入 routes / middleware / handlers
    ↓
SharedStore<RatePolicy> extractor 按类型取值

AppContext 只创建一次并被后续组件共享。SharedStore 用 Rust TypeId 做类型索引，不用字符串 key，所以取值类型必须完全一致。

2. 在 after_context 中构建服务

#[derive(Clone)]
struct RatePolicy {
    max_per_minute: u32,
}

#[derive(Debug, Deserialize)]
#[serde(default)]
struct AppSettings {
    rate_limit_per_minute: u32,
}

impl Default for AppSettings {
    fn default() -> Self {
        Self { rate_limit_per_minute: 60 }
    }
}

#[async_trait]
impl Hooks for App {
    async fn after_context(ctx: AppContext) -> Result<AppContext> {
        let settings: AppSettings = ctx.config.settings()?;
        ctx.shared_store.insert(RatePolicy {
            max_per_minute: settings.rate_limit_per_minute,
        });
        Ok(ctx)
    }
}

这里用 ? 是合理的，因为 after_context 返回 Result<AppContext>；错误配置可以在启动阶段失败，而不是第一个请求才 panic。

3. 在 handler 中注入

async fn stats(
    SharedStore(policy): SharedStore<RatePolicy>,
) -> Result<Response> {
    tracing::info!(limit = policy.max_per_minute, "using rate policy");
    format::json(serde_json::json!({
        "limit": policy.max_per_minute
    }))
}

找不到类型时，SharedStore<T> extractor 会返回内部错误并记录类型名。需要共享可变状态时，通常存入 Arc<Mutex<T>> 或专门的并发容器，而不是把裸可变值塞进去。

4. 和其他注入方式比较

方式适合
State<AppContext>数据库、配置、Loco 已有基础设施
SharedStore<T>应用自定义服务、策略、客户端、缓存包装器
Json / Path / Query来自当前 HTTP 请求的数据
