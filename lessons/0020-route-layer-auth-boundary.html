Routes::layer 与 JWT extractor：边界放对位置

目标：看到一组路由时，能判断逻辑应该放在局部 layer，还是放进 handler 参数里的认证 extractor。

1. 先记住两种职责

机制适合放什么范围
Routes::layer日志、超时、限流、统一响应头这个 Routes 已注册的所有 handler
auth::JWT验证 token，拿到 claims声明了 extractor 的那个 handler
auth::JWTWithUser<T>验证 token，并从数据库加载用户声明了 extractor 的那个 handler

Loco 官方把 Routes::layer 定义为路由组级别的 Tower layer；JWT 则是 Axum extractor，在 handler 执行前完成认证。详见 Add middleware 与 Protect a Route with JWT。

2. 一个 admin 路由组

use axum::{extract::Request, middleware};
use loco_rs::prelude::*;
use std::time::Instant;

async fn admin_trace(req: Request, next: middleware::Next) -> Response {
    let method = req.method().clone();
    let uri = req.uri().clone();
    let started = Instant::now();

    let response = next.run(req).await;

    tracing::info!(
        %method,
        %uri,
        status = response.status().as_u16(),
        elapsed_ms = started.elapsed().as_millis(),
        "admin request finished"
    );
    response
}

pub fn routes() -> Routes {
    Routes::new()
        .prefix("api/admin/")
        .add("ping", get(ping))
        .add("products", get(products))
        // 放在 add 之后，套住已经注册的路由
        .layer(middleware::from_fn(admin_trace))
}

3. 认证仍然写在 handler 参数里

async fn products(
    auth: auth::JWTWithUser<users::Model>,
    State(ctx): State<AppContext>,
) -> Result<Response> {
    tracing::info!(user_pid = %auth.user.pid, "list products");
    format::json(products::Entity::find().all(&ctx.db).await?)
}

一次请求的简化顺序是：admin_trace 进入 → JWTWithUser 验证并查用户 → products handler → layer 记录响应。layer 不应该偷偷替代用户 extractor 做业务授权。

4. 这一课的判断题

  1. 只给 admin 路由加 5 秒超时：放在 Routes::layer。
  2. 判断当前用户能不能删除某个 category：在 handler 中使用 JWTWithUser，再调用模型的授权规则。
  3. 所有路由都要 CORS：放全局 server.middlewares 配置。
