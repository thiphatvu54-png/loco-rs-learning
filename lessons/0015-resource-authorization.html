资源级授权：当前用户能不能改这条数据

目标：把“已登录”进一步变成业务规则：只能修改自己的资源，管理员才能删除。

1. 三步授权

  1. JWTWithUser 验证 token 并加载当前用户。
  2. 查询目标资源。
  3. 比较当前用户和资源的 owner/role，再决定 200、403 或 404。
async fn update_profile(
    auth: auth::JWTWithUser<users::Model>,
    State(ctx): State<AppContext>,
    Path(id): Path<i64>,
) -> Result<Response> {
    let Some(profile) = profiles::Entity::find_by_id(id).one(&ctx.db).await? else {
        return Err(Error::NotFound);
    };

    if profile.owner_pid != auth.user.pid {
        return Err(Error::Forbidden);

}

当前项目的 categories 没有 owner 字段，所以不能凭空实现“只能改自己的分类”；要先有领域字段或角色，再写授权规则。

2. 401、403、404 的区别

状态含义
401没有有效身份，或 JWTWithUser 找不到用户
403身份有效，但没有操作权限
404资源不存在；也可有意隐藏资源存在性
隐藏资源存在性：有些系统会把“不是你的资源”也返回 404，避免泄露资源 id。选择 403 还是 404 是产品和安全策略，不是 extractor 自动决定的。

  3. 说明“用户不存在”和“用户存在但无权限”分别返回什么。
