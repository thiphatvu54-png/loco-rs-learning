Middleware Pipeline：请求经过哪些门

目标：知道全局中间件写在哪里、单路由中间件写在哪里，以及为什么顺序是 LIFO。

1. 全局中间件来自配置

server:
  middlewares:
    compression:
      enable: true
    cors:
      enable: true
    timeout_request:
      enable: true
      timeout: 10s

配置驱动的中间件会作用于所有路由。查看当前解析结果：

cargo loco middleware --config

不要只写一个 key 就以为启用成功；某些默认启用的中间件一旦写进配置，必须显式写 enable: true。

2. 单个 controller 使用 Routes::layer

pub fn routes() -> Routes {
    Routes::new()
        .prefix("/api/admin")
        .layer(my_tower_layer)
        .add("/ping", get(ping))
}

只想影响一个 controller 或一组路由时，用 Routes::layer；不要把局部限流或特殊 header 配成全局行为。

3. LIFO：最后添加，最先进入

Vec<Layer>: [A, B, C]

请求进入：C → B → A → handler
响应返回：handler → A → B → C

这和直觉中的“从左到右”相反。把自定义 layer 放到 vec 的末尾，意味着它更靠近外部请求；放到前面，意味着它更靠近 handler。

  3. 画出三个 layer 的请求进入顺序和响应返回顺序。
