结构化日志：让错误能被定位

目标：用 tracing 记录“发生了什么、关联哪个对象、结果如何”，并按环境切换日志级别和格式。

1. 日志不是随便打印字符串

tracing::info!(
    job_id = %job_id,
    user_pid = %user.pid,
    "download job enqueued"
);

消息是人读的，字段是机器筛选的。以后在日志平台里可以按 job_id 或 user_pid 找完整链路。

失败时保留错误上下文，但不要打印密码、JWT secret 或完整 token：

if let Err(err) = do_work().await {
    tracing::error!(error = %err, user_pid = %pid, "download failed");
    return Err(err);
}

2. 按环境选择级别和格式

环境典型 level典型 format目的
developmentdebugcompact本地排查
testdebugcompact减少噪声
productioninfojson交给日志聚合器

当前项目的生产配置已经使用 JSON；日志级别可以通过 LOG_LEVEL 覆盖：

$env:LOG_LEVEL = "debug"
cargo loco start
Remove-Item Env:LOG_LEVEL

3. 快速练习

  1. 给 Worker 的成功日志加上 job_id 或用户标识字段。
  2. 给失败分支加 tracing::error!，只记录错误文本和业务 id。
  3. 比较 development 的 compact 输出和 production 的 JSON 配置。
