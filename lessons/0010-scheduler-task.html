定时任务：Scheduler 只管时间，Task 负责工作

目标：把“一次手动执行”和“每天自动执行”拆成两个清楚的部件。

1. 三种触发方式

机制触发者代码位置
Task人或 Schedulersrc/tasks/*.rs
BackgroundWorker请求或代码src/workers/*.rs
Scheduler时钟config/<env>.yaml 或专用 scheduler 文件

Scheduler 不应该塞业务逻辑。它只在指定时间运行一个已经注册的 Task。你项目里的 user:create 和 user:delete 已经是可手动运行的 Task。

2. 先确认 Task，再安排时间

cargo loco task

这会列出 Hooks::register_tasks 注册的任务。运行任务的通用格式是：

cargo loco task <TASK_NAME> [KEY:VALUE ...]

例如项目已有：

cargo loco task user:delete pid:01H... force:true

Scheduler 的 run 字段写的就是这段任务名和参数，不是 Rust 函数名。

3. 写一个定时配置

生成专用文件：

cargo loco generate scheduler

然后编辑 config\scheduler.yaml：

output: stdout
jobs:
  purge_demo:
    run: "user:delete pid:01H... force:true"
    schedule: "at 3:00 am"
    tags: ["maintenance"]

  quick_check:
    run: "user:create email:demo@example.com name:Demo password:secret123"
    schedule: "run every 30 seconds"
    run_on_start: false

专用文件要显式传给 CLI：

cargo loco scheduler --config config/scheduler.yaml --list
cargo loco scheduler --config config/scheduler.yaml --name quick_check

如果把配置写进 config\development.yaml 的 scheduler: 区块，才可以直接运行 cargo loco scheduler --list。Cron 表达式有秒这一列；初学时用英文时间表达式更不容易错。

安全边界：生产环境不要把真实密码直接写进 scheduler 文件。定时任务应该调用一个幂等的清理/报告 Task，敏感值从环境变量或数据库读取。

4. 快速练习

  1. 运行 cargo loco task，指出列表里的 Task 名称。
  2. 创建一个只打印日志的 daily_report Task，注册到 Hooks::register_tasks。
  3. 在 scheduler 配置里让它每天 09:00 运行。
  4. 用 --list 检查解析结果，再用 --name daily_report 手动触发一次。
