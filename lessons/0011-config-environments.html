配置与环境：同一份代码，不同的运行边界

目标：看懂 Loco 如何选择配置文件，并知道 JWT_SECRET、DATABASE_URL 这类值应该放在哪里。

1. Loco 先选环境，再读 YAML

环境名默认文件当前项目用途
developmentconfig/development.yaml本地开发
testconfig/test.yaml测试 SQLite、同步 Worker
productionconfig/production.yaml部署环境

LOCO_ENV 优先决定环境；没有设置时默认是 development。同一环境还可以有 *.local.yaml，它按键覆盖主文件，适合机器本地配置。

2. PowerShell 切换环境

$env:LOCO_ENV = "test"
cargo loco doctor
Remove-Item Env:LOCO_ENV

也可以直接检查生产配置：

$env:LOCO_ENV = "production"
$env:JWT_SECRET = "base64-secret-from-secret-manager"
$env:DATABASE_URL = "sqlite://production.sqlite?mode=rwc"
cargo loco doctor
Remove-Item Env:LOCO_ENV
Remove-Item Env:JWT_SECRET
Remove-Item Env:DATABASE_URL

3. 默认值和必填值

配置里的 get_env 是渲染阶段读取环境变量：

server:
  port: <%= get_env(name="PORT", default="5150") %>

auth:
  jwt:
    secret: <%= get_env(name="JWT_SECRET") %>

有 default 的值可以省略；没有 default 的值缺失时应该让应用启动失败。生产配置不应该悄悄退回开发密钥或 localhost 数据库。

安全规则：提交 YAML 模板和变量名，不提交真实 JWT secret、数据库密码或 SMTP 密码。生产配置的“启动失败”比带着错误密钥启动更安全。

4. 快速练习

  1. 查看 development.yaml、test.yaml、production.yaml 中的 workers.mode 和 database.uri。
  2. 设置 $env:LOCO_ENV = "test"，运行 cargo loco doctor，再清理环境变量。
  3. 解释为什么 production 的 JWT_SECRET 没有默认值。
